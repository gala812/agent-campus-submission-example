# 05 复盘与后续

## 个人实验复盘

以下以本人视角表述，由AI根据本人实际执行的实验协助整理。实际用时由本人提供；不将AI辅助编写的代码、测试和分析称为本人独立完成。

### 我的参与与投入

我的背景主要是科研问答，因此选择了企业知识问答这一题。我参与了需求确认和技术选择，配置DeepSeek密钥，并在本机运行冲突问答、资料修改前后对照和一次工具失败注入。我修改的是合成知识库副本中的P01内容与版本日期，没有独立实现项目源码。代码、测试与文档整理使用了Codex辅助，具体范围见 [AI使用记录](04-ai-usage.md)。

本人累计实际投入约 **2小时**，包括阅读考核要求、配置模型、执行实验、检查结果及整理提交材料。这是本人估算，不是精确计时；没有为各环节虚构耗时。该时间与AI辅助开发的墙钟时间可能重叠，不直接相加。

### 重点问题：如何判断Agent真的依据结果调整了动作

这次实验中，我重点关注的是如何区分“最终回答正确”和“执行过程合理”。冲突实验同时检索到30天和15天两种制度，Agent读取双方原文后继续查询适用范围、优先级和替代关系；查不到足够依据时，它返回需要澄清，没有仅凭日期较新就选15天。这个过程说明，面对企业制度问题，信息不足时明确保留不确定性也是合理结果。

资料修改对照中，我把P01从“支持自动生成中文字幕”改为“不支持自动生成字幕，仅支持手动输入和编辑字幕”，并更新版本日期。相同问题的答案随后从“支持”变成“不支持”，引用也对应新原文。这个实验验证了当前用例会随资料变化调整回答，但不能据此推断所有问法都能正确处理。

### 失败注入后的动作与收获

失败注入时，检索已经成功，第一次读取P01却返回工具暂时不可用。模型随后再次选择读取同一文档，保留已有检索结果；第二次读取成功后才回答。最终状态是answered，表示故障恢复后任务完成，不表示每一步都成功。判断失败处理是否有效，应查看Trace中的错误、后续动作和引用来源，不能只看最后的状态。这里的重试由模型在收到错误后选择，工具执行器没有自动重试。

### 为什么引用一致仍不等于结论正确

引用字面一致只能说明片段确实来自已读文档，还需要判断它能否支持回答。例如，“支持自动生成中文字幕”不能推出“效率提升80%”；准确引用D02的15天，也不能在忽略D01冲突的情况下断言统一期限就是15天。我在评估这类系统时需要同时关注引用真实性、结论是否超出证据、适用范围和未解决的冲突。

### 下一步优先改进

如果继续完善，我会优先增加未参与检索规则设计的问题，包括改写、否定表达和制度适用范围，再比较召回结果与回答依据是否完整。其次增加持续工具故障和多次真实运行，检查停止条件及行为稳定性。当前仍缺少更大独立测试集、系统性的语义支持评估和企业权限管理，这些属于后续工作。

本节依据的四次真实运行及原始Trace见 [个人实验记录](../examples/personal/README.md)。

## AI辅助开发中的工程难点

**接口支持工具调用，不代表每次只返回一个动作。** 初次真实冲突用例中，DeepSeek同轮选择读取D01和D02，旧实现拒绝多个调用，导致多次无效协议纠正。诊断只打印调用数量与工具名，确认返回了两个read_document。随后改为逐个执行、分别回传，并独立约束工具总数。新增同轮多调用、限额与finish混用的回归测试。原始失败Trace保存在 `examples/history/live-before-protocol-fix/`。

**查询改写可能扩大噪声。** 初始Mock无结果后添加“资料”一词，误召回不相关制度，把资料外问题错误转成制度冲突。修复时去掉无意义的泛词，保留主体词。初始13个离线用例中12个通过，修改后13个通过。这个改进只证明模拟流程修复，不证明模型检索能力提高。

**字符串溯源与语义正确是两回事。** 精确匹配原文可以阻止伪造片段，却不能阻止“引用是真的、结论却错误”。因此自动验收检查关键事实与状态，同时保留完整原始输出做语义审阅；文档不把引用校验称为事实正确性保证。

**环境兼容性必须实测。** 本机Python为3.8，最初构建辅助脚本使用了较新Path.write_text的newline参数而失败。改成兼容的文件打开方式后继续；交付源码和测试已在当前解释器实际运行。首次代码提交还通过了GitHub上Python 3.8/3.11/3.13三项CI，见[记录](../examples/github-ci.json)。

## 本轮工程收获

- 先把真实模型接口打通，才能发现Mock无法揭示的协议差异。
- 工具、模型和任务状态需要分开：工具失败不是模型失败，正确拒答也不是测试失败。
- 提示模型谨慎之外，仍需要代码约束引用、同主题候选阅读和执行预算。
- 测试预期必须来自验收要求，并与模型输入隔离；不能向模型传expected。
- 检索改进要做对照，且明确开发集与独立测试集的区别。

以上工程发现由AI依据开发记录整理；候选人的实际操作与AI协助整理的第一人称复盘见本页前文，两者不混同为独立开发经历。
